# v0.3.0 — Float steering, live feel tuning, and one FFB truth

The quality release: the whole FFB path was rebuilt around a single tested
composition, the feel loop now reacts to the physical wheel, every gain is
live-tunable, and wheel mounts can take steering and brake as exact floats.

Start with
[TESTING.md](https://github.com/Cmiller132/aeronautics-simwheel/blob/v0.3.0/TESTING.md)
for the release-to-first-drive walkthrough.

## For testers

- **Float mount linking (new).** Hold a stick, click the wheel, click the
  steered wheel mounts, click the wheel again — those mounts now take
  steering and brake with no redstone quantization at all. Unlink the same
  way. See the new section in
  [TESTING.md](https://github.com/Cmiller132/aeronautics-simwheel/blob/v0.3.0/TESTING.md).
- **Live feel tuning (new).** Every feel and safety gain lives in
  `config/aeronautics_simwheel-feel.toml` (written with commented defaults
  on first launch). Edit while driving; saves apply on the next corner.
  Broken edits keep the last good values. Send us numbers that feel great.
- **The soft lock now works** against the physical wheel: with the bridge
  running, turn past the configured lock and you hit the wall — previously
  this could never fire. Damper/friction also run on true wheel velocity
  now instead of a 20 Hz snapshot.
- **Pedals that never bound, now bind** (GLFW axis discovery bug), and
  toggling the demo input off no longer strands a connected wheel.
- The HUD gained an FFB loop-stats line (`loop … Hz late …`) and a
  feel-config status line — both useful in reports.

## Under the hood

- One `FfbPipeline` composition is now shared by the mod, the unit tests,
  and the offline regression harness — the class of "test passed, shipping
  wiring differed" bugs is structurally gone. New `FfbService` owns the
  250 Hz loop with absolute-deadline pacing.
- Torque is **Nm end-to-end** through the HAL (a hardcoded rated-torque
  conversion that rescaled the safety clamp on non-R9 bases is gone).
- A sidecar-reported device fault now panics the safety chain (it was
  previously decoded and ignored); faults clear only on deliberate
  re-engage.
- First (and only) mixin: `WheelMountBlockEntityMixin` feeds linked mounts
  float `computeYaw`/`brakeStrength` — `require = 0`, so an Offroad update
  degrades linked mounts to stock instead of crashing, and the new startup
  **health check** runs seven probes over the reaches that can drift silently:
  S1, S3, S6, S7, S8 (two probes), and S9. S2, S4, and S5 are conventions or
  standard APIs that are not probed. Success logs
  `SimWheel health check: all 7 integration surfaces verified`.
- Server input path gained a per-sender rate gate; the sidecar gained
  clean SIGINT/SIGTERM and Ctrl-C shutdown, which stops output and erases the
  effect instead of waiting for the 250 ms hardware lease to expire. Strict
  `--port`/`--device` parsing now errors instead of silently saturating.
- Test harness only: the ground-telemetry gametest failed on about 40% of
  Windows runs when its craft tipped onto one wheel mid-measurement, leaving
  three tires airborne and no steered tire in ground contact. Steering and
  telemetry were working in those runs; the defect was the test rig, not
  shipped behavior. The craft is now held in a deterministic kinematic rig
  for the measurement window. No assertion was weakened, and a new assertion
  proves link steering reaches both front mounts.
- Docs: full rewrite — `docs/DESIGN.md` now describes the system as built;
  every major directory has a file-by-file `README.md`; `AGENTS.md` orients
  coding agents.

Verified on the Windows release machine on 2026-08-14, in sim mode with no
wheel hardware attached: the engine suite passed 86 tests (0 failures, 0
skipped); cross-language sidecar conformance (the real mod client against the
real sidecar over live UDP) passed; all 6 required gametests plus the startup
health check 7/7 stayed green for 20 consecutive runs; the client selftest
passed; and sidecar unit tests passed 16/16 on Windows and 22/22 on Linux. A
Linux end-to-end run against the real release binary over live UDP also passed
handshake, deflection, watchdog decay and recenter, panic latch, and recovery
(5/5). Hardware-in-the-loop on a real MOZA R9 has still never run; it remains
the open frontier (`sidecar/README.md` checklist).

The wire protocol did not change, so a 0.2.0 bridge still works with the
0.3.0 mod and a 0.3.0 bridge works with the 0.2.0 mod. Upgrading the bridge is
recommended for clean shutdown and strict argument parsing, but not required.

## Upgrading from 0.2.0

Import the new mrpack as a fresh instance (or drop the new jar into
`mods/`). Upgrade to the 0.3.0 bridge for clean shutdown and strict argument
parsing; the 0.2.0 bridge remains wire-compatible if you need to keep it. The
feel TOML is new — it writes itself with commented defaults on first launch.
